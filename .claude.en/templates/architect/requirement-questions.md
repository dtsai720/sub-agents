# 雲端架構需求問題模板

此模板供 Cloud Architect Agent 使用，當需求不完整時，從以下類別選擇適當問題詢問使用者。

## 使用指引

- **必問類別**：基礎需求、雲端平台（如未提供）
- **依情況選擇**：技術架構、安全性、部署運維、成本預算
- **問題數量**：簡單專案 5-8 題，複雜專案 10-15 題
- **過濾原則**：略過使用者已回答的問題

---

## 1. 基礎需求（必問）

### 1.1 業務需求
- **專案目標是什麼？** 解決什麼業務問題？
- **主要功能有哪些？** 列出 3-5 個核心功能
- **目標使用者是誰？** 內部員工、外部客戶、合作夥伴？
- **預期使用者規模？**
  - [ ] < 100 使用者
  - [ ] 100-1000 使用者
  - [ ] 1000-10000 使用者
  - [ ] > 10000 使用者

### 1.2 資料需求
- **主要資料實體有哪些？** 例如：使用者、訂單、產品
- **資料之間的關聯關係？** 一對一、一對多、多對多？
- **預期資料量級？**
  - [ ] < 10 萬筆
  - [ ] 10-100 萬筆
  - [ ] 100 萬-1000 萬筆
  - [ ] > 1000 萬筆

### 1.3 非功能性需求
- **效能需求？**
  - 預期 QPS/TPS（每秒請求數）：______
  - API 回應時間要求：______ ms
- **可用性需求？**
  - [ ] 一般（99%，年停機約 3.65 天）
  - [ ] 高可用（99.9%，年停機約 8.76 小時）
  - [ ] 極高可用（99.99%，年停機約 52.6 分鐘）
- **是否需要支援高併發？** 預期最高同時在線人數：______

## 2. 雲端平台（必問 - 如未提供）

### 2.1 平台選擇
- **偏好使用哪個雲端平台？**
  - [ ] AWS（Amazon Web Services）
  - [ ] Azure（Microsoft Azure）
  - [ ] GCP（Google Cloud Platform）
  - [ ] 無偏好，請根據需求推薦

### 2.2 既有雲端資源
- **目前是否已有雲端環境？**
  - [ ] 是（平台：______ ，服務：______ ）
  - [ ] 否（全新專案）

---

## 3. 技術架構（依情況詢問）

### 3.1 架構模式偏好
- **偏好的架構模式？**
  - [ ] Monolith（單體應用）- 適合小型專案
  - [ ] Microservices（微服務）- 適合複雜業務、多團隊協作
  - [ ] Serverless（無伺服器）- 適合事件驅動、不規則流量
  - [ ] 無偏好，請推薦

### 3.2 資料庫偏好
- **偏好的資料庫類型？**
  - [ ] 關聯式資料庫（PostgreSQL/MySQL）- 適合結構化資料、複雜查詢
  - [ ] NoSQL（DynamoDB/MongoDB）- 適合非結構化資料、高擴展性
  - [ ] 混合使用
  - [ ] 無偏好，請推薦

### 3.3 API 設計
- **需要哪些 API 操作？**
  - [ ] 僅讀取（Read-only API）
  - [ ] CRUD（Create, Read, Update, Delete）
  - [ ] 複雜業務邏輯（搜尋、篩選、聚合、報表）

### 3.4 前端需求
- **是否需要前端介面？**
  - [ ] 需要（Web 應用）
  - [ ] 需要（Mobile App）
  - [ ] 僅提供 API（供第三方串接）
  - [ ] 未決定

## 4. 安全性（依情況詢問）

### 4.1 認證與授權
- **認證機制？**
  - [ ] 已有上游認證服務（如：API Gateway 處理認證，傳入 user-id/tenant-id）
  - [ ] 需要自行實作（JWT/OAuth2/API Key）
  - [ ] 公開 API（無需認證）

### 4.2 資料安全
- **是否處理敏感資料？**
  - [ ] 是（個資、金融資料、健康資料）
  - [ ] 否
- **是否需要資料加密？**
  - [ ] 傳輸加密（HTTPS/TLS）
  - [ ] 儲存加密（Database Encryption）
  - [ ] 兩者都需要

### 4.3 合規需求
- **是否有合規要求？**
  - [ ] GDPR（歐盟個資保護）
  - [ ] HIPAA（美國健康資料）
  - [ ] PCI DSS（金融支付）
  - [ ] 無特殊合規需求

## 使用範例

### 簡單專案（CRUD API）範例問題
```markdown
## ⚠️ 需求資訊不足，需要補充

為了設計出符合需求的雲端架構，請協助回答以下問題：

### 基礎需求
1. 預期使用者規模？（< 100 / 100-1000 / > 1000）
2. 主要資料實體有哪些？（例如：使用者、訂單、產品）
3. 預期資料量級？（< 10萬筆 / 10-100萬筆 / > 100萬筆）

### 雲端平台
4. 偏好使用哪個雲端平台？（AWS / Azure / GCP / 無偏好）

### 技術需求
5. 偏好的資料庫類型？（PostgreSQL / MySQL / NoSQL / 無偏好）

### 安全性
6. 認證機制？（已有上游服務 / 需自行實作 / 公開API）

### 部署需求
7. 偏好的部署方式？（Serverless / Container / VM / 無偏好）

請提供以上資訊後，我將開始設計架構。
```

### 複雜專案（微服務）範例問題
```markdown
## ⚠️ 需求資訊不足，需要補充

此專案涉及多個業務領域，需要更詳細的需求資訊：

### 基礎需求
1. 專案目標是什麼？解決什麼業務問題？
2. 主要功能有哪些？列出 3-5 個核心功能
3. 預期使用者規模與併發量？（QPS、同時在線人數）
4. 主要資料實體及其關聯關係？

### 雲端平台
5. 偏好使用哪個雲端平台？（AWS / Azure / GCP）
6. 是否已有既有雲端環境或服務需整合？

### 技術架構
7. 偏好的架構模式？（Monolith / Microservices / Serverless）

### 安全性
9. 是否處理敏感資料？需要哪些加密措施？
10. 認證與授權機制？（JWT / OAuth2 / 上游服務）

### 非功能性需求
11. 可用性需求？（99% / 99.9% / 99.99%）
```

## 注意事項

1. **動態調整問題**：根據使用者已提供的資訊，過濾掉重複問題
2. **問題精簡**：簡單專案不要問太多問題，避免使用者負擔過重
3. **提供選項**：多用選擇題，減少開放式問答
4. **解釋用途**：適時說明為什麼需要這個資訊（例如：「為了選擇適合的資料庫」）
5. **允許無偏好**：對於技術選型問題，允許使用者回答「無偏好，請推薦」
