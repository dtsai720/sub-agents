# 功能重複檢查機制

當進入產品開發流程時，Orchestrator 必須執行功能重複檢查，避免重複開發。

## 觸發時機

- 產品經理 Agent 產出 PROD.md 後
- 在進入 UI/UX 設計階段前
- 目的：確認系統中是否已有類似功能

## 執行步驟

### 步驟 1：調用後端開發 Agent 進行功能搜尋

```javascript
Task(
  subagent_type: "general-purpose",
  description: "後端開發 Agent 執行功能重複檢查",
  prompt: `
你是專業的後端開發 Agent。

## 特殊任務：功能重複檢查

請分析專案中是否已有類似功能。

## 輸入
PROD.md 的核心功能描述：
- 功能：關閉 issue 並通知團隊成員
- 用戶故事：當用戶關閉 issue 時，系統應自動通知相關團隊成員

專案路徑：{project_path}

## 分析要求
1. 搜尋專案中的 API 端點、服務、模組
2. 基於功能語義（不只是名稱）進行比對
3. 評估相似度（高 > 70% / 中 40-70% / 低 < 40%）
4. 說明差異

## 輸出格式

### 現有功能分析報告

**搜尋關鍵字：** 關閉 issue、通知、團隊

**找到的類似功能：**

1. **功能名稱：** close issue API
   - **路徑：** src/api/issues.go:45
   - **功能描述：** 關閉 issue 並更新資料庫狀態
   - **相似度：** 高（80%）
   - **差異：**
     * 現有：關閉 issue + 更新狀態
     * 缺少：通知團隊成員功能
   - **技術棧：** Go + Gin

2. **功能名稱：** notification service
   - **路徑：** src/services/notification.go:20
   - **功能描述：** 發送各種類型的通知
   - **相似度：** 中（50%）
   - **差異：**
     * 現有：通用通知服務
     * 缺少：與 issue 關閉的整合

**建議：**
- **推薦方案：** 增強現有 close issue API，整合 notification service
- **原因：** 功能高度重疊（80%），避免重複開發
- **預估工作量：** 修改現有 API（2-3 小時）vs 全新開發（1-2 天）

**若未找到類似功能：**

### 現有功能分析報告

**搜尋關鍵字：** [從 PROD.md 提取]

**搜尋結果：** 未找到類似功能

**確認：** 可以安全地進行新功能開發，無重複風險
`
)
```

### 步驟 2：Orchestrator 分析結果並決策

```
若找到類似功能（相似度 > 40%）：
  → 向用戶展示分析結果
  → 提供選擇：增強現有 / 建立新功能 / 直接使用

若未找到類似功能：
  → 確認無重複
  → 繼續產品開發流程
```

### 步驟 3：向用戶確認（若找到類似功能）

```
Orchestrator 回應：
「我在系統中找到以下類似功能：

📍 **close issue API** (src/api/issues.go:45)
- 功能：關閉 issue 並更新資料庫狀態
- 相似度：80%（高度相似）
- 差異：目前沒有通知團隊成員功能

📍 **notification service** (src/services/notification.go:20)
- 功能：發送各種類型的通知
- 相似度：50%（中度相似）
- 差異：需要整合到 issue 關閉流程

💡 **建議方案：** 增強現有 close issue API，整合 notification service

**預估工作量：**
- 增強現有功能：2-3 小時
- 全新開發：1-2 天

**請選擇：**
1. [ ] 增強現有 close issue API（推薦）
   → 將轉入「現有專案增強流程」

2. [ ] 建立全新的 API
   → 繼續「產品開發流程」
   → 架構師會確保與現有功能不衝突

3. [ ] 直接使用現有功能
   → 我將提供現有 API 的使用文件
」
```

### 步驟 4：基於用戶選擇執行流程

```
選項 1（增強現有）：
  → 轉入「現有專案增強流程」
  → 跳過 UI/UX 和架構設計（已有基礎）
  → 直接進入開發階段

選項 2（建立新功能）：
  → 繼續「產品開發流程」
  → 將「現有功能分析報告」傳給架構師
  → 架構師設計時確保不衝突

選項 3（直接使用）：
  → 產出現有 API 的使用文件
  → 結束流程
```

## 關鍵原則

- ✅ 自動化檢測，減少人工遺漏
- ✅ 透明化分析結果，讓用戶理解建議原因
- ✅ 用戶保留最終決策權
- ✅ 提供工作量預估，協助決策
- ✅ 避免技術債和重複代碼
